# Machine Learning Delay Prediction Engine

**Project**: Maximizing Section Throughput Using AI-Powered Precise Train Traffic Control  
**Module**: `ml/`  

---

## 1. Overview & Objective

The Machine Learning Delay Prediction Engine forecasts train arrival delays based on real-time kinematic telemetry and section traffic congestion. These predicted delays serve as forward-looking inputs to the multi-objective AI optimization engine, enabling proactive overtakes before delays cascade across block sections.

> **Academic Notice**: Predictions generated by this system are decision-support indicators derived from synthetic operational modeling and are not certified for safety-critical signaling operations.

---

## 2. Training Dataset Generation

- **File**: `data/train_delay_dataset.csv`
- **Samples**: 6,500 synthetic train operational records
- **Split**: 80% Training (5,200 samples), 20% Testing (1,300 samples)
- **Random Seed**: 42 (reproducible)

The dataset incorporates realistic delay propagation dynamics:
- High priority Express trains experience lower base delays and faster clearance.
- Saturated sections ($>75\%$ utilization) trigger non-linear queueing delays.
- Waiting trains at signal bottlenecks accumulate secondary waiting delays.

## 3. Feature Pipeline

The preprocessor pipeline (`preprocessing_pipeline.pkl`) standardizes numerical features and one-hot encodes categorical variables:

### 3.1. Numerical Features (11)
Standardized using `StandardScaler`:
1. `scheduled_duration`: Timetable trip duration (minutes)
2. `distance_remaining_km`: Distance to final destination station (km)
3. `current_speed_kmph`: Observed train speed (km/h)
4. `maximum_speed_kmph`: Section civil speed limit (km/h)
5. `current_delay_minutes`: Observed delay at current time step (minutes)
6. `number_of_stops_remaining`: Remaining intermediate station calls
7. `station_dwell_time`: Expected station dwell duration (minutes)
8. `number_of_trains_in_section`: Total trains currently occupying section
9. `section_utilization`: Section capacity load percentage ($0-100\%$)
10. `traffic_density`: Overall corridor density percentage ($0-100\%$)
11. `waiting_train_count`: Trains queued behind red block signals

### 3.2. Categorical Features (4)
Encoded using `OneHotEncoder(handle_unknown='ignore')`:
1. `train_type`: `EXPRESS`, `PASSENGER`, `LOCAL`, `FREIGHT`
2. `priority`: `HIGH`, `MEDIUM`, `LOW`
3. `time_of_day`: `MORNING`, `AFTERNOON`, `EVENING`, `NIGHT`
4. `day_type`: `WEEKDAY`, `WEEKEND`

## 4. Model Benchmarking & Performance

Four regressor families were trained and evaluated on identical test splits:

| Algorithm | Mean Absolute Error (MAE) | Root Mean Squared Error (RMSE) | $R^2$ Score |
| :--- | :--- | :--- | :--- |
| Ordinary Least Squares | 1.589 min | 2.073 min | 0.9250 |
| Random Forest Regressor (100 trees) | 1.297 min | 1.736 min | 0.9474 |
| Gradient Boosting Regressor | 0.868 min | 1.133 min | 0.9776 |
| **HistGradientBoostingRegressor (Selected)** | **0.851 min** | **1.118 min** | **0.9782** |

`HistGradientBoostingRegressor` was chosen for its sub-millisecond inference latency, native binning efficiency, and superior generalization accuracy.

## 6. Model Management & Lifecycle

1. **Training Script**: `python -m ml.models.train_model`
   - Re-trains model, regenerates benchmarks, serializes pipeline, and updates `model_metadata.json`.
   - **No Silent Training**: The backend server **never** trains models automatically on startup; it only loads pre-serialized artifacts.
2. **Evaluation Script**: `python -m ml.models.evaluate_model`
3. **Inference Service**: `ml.models.predict.DelayPredictionService`
   - Lazy in-memory artifact caching.
   - Graceful fallback: if artifacts are missing, returns `status: "Unavailable"` without terminating the server.
